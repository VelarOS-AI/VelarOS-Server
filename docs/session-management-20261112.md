# 会话管理差量

登录后默认选中一个新会话，连续点击「+」复用该空白入口，保留当前未发送草稿。客户端在网络回执前即可展示；服务端创建也复用尚未使用的未归档空会话，不因不同窗口或新 UUID 创建重复空行。首次发送仍将消息立即投影，正式回显使用服务端确认的会话身份接管。

侧栏每行通过共享菜单提供重命名、置顶/取消置顶和归档；底部只有「已归档」入口，归档列表可查看原消息、重命名和取消归档。置顶在普通列表优先显示，其他会话按更新时间排列。归档清除置顶，运行中的会话不能归档；归档不会删除消息、取消任务或重放命令。已归档记录不能接收新输入，原 requestId 仍可获得原回执，恢复后正常使用。

产品合同增加必填 pinned/archived 布尔字段和 SessionUpdate；HTTP 增加严格 PATCH，名称去空白后 1–100 字符。组织信息归独立 session_metadata 表，原 schema 2 运行投影和数据继续使用，不增加旧格式解析或迁移层，也不清理已有聊天。新字段初始均为普通、未归档；命名覆盖和标记不被执行投影重写。持久 revision 从数据库当前值递增，客户端按 revision 合并，迟到列表不覆盖刚完成的修改或创建。

本批集中通过格式、Server/Web 类型、HTTP/SQLite 管理接缝 2 项、会话投影 4 项、接纳原子性 4 项、实时正文与重启 2 项及网页构建。独立浏览器在创建延迟 2500ms 时验证默认一条新会话、多次点击复用且保留草稿、命名、置顶、归档、历史查看、恢复和刷新持久化，无 error。测试未调用供应商模型；Linux 制品和线上部署另记精确源码与清单校验，不替代历史 Host 隔离证明。
